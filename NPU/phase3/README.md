## 2. NPU-P3-01：固定测试矩阵

| 维度 | 取值与约束 |
| --- | --- |
| batch | 1、8、32，使用匹配的静态或合法动态模型 |
| 并发 | 1、2、4 个独立请求槽；并发不等于使用更多设备 |
| 负载 | Phase 2 MLP；另选一个有授权权重和真实标签的模型作扩展 |
| 类型 | FP32/FP16 有效计算模式；支持时增加 BF16、INT8 |
| 统计 | 冷启动单列；稳态预热 10 次、测量至少 100 次、至少三轮 |

先实现单请求同步基线。端到端使用主机单调时钟，包含 H2D、执行、D2H 和显式同步；设备事件按实际 CANN/框架 API 使用，不把异步函数返回计作完成。吞吐为完成样本数除以同一窗口墙钟时间，不用并发请求延迟的倒数简单相加。

框架内计时示例，`model`、`x` 需先按 Phase 2 的相同权重和输入放入 NPU，预热后执行：

```python
import time

torch.npu.synchronize()
start = time.perf_counter()
with torch.no_grad():
    for _ in range(100):
        output = model(x)
torch.npu.synchronize()
elapsed = time.perf_counter() - start
print("mean_device_resident_request_ms:", elapsed * 1000 / 100)
```

这段只测设备驻留输入的串行提交与最终完成，不包含主机输入输出传输，也不提供逐请求尾延迟。另采每次同步后的样本才能分析请求延迟分布。

## 3. NPU-P3-02：精度检查

固定权重、预处理及测试集；对每种实际计算配置保存输出，以 CPU/高精度框架为参考。报告最大绝对误差、相对误差、非有限值；分类模型补充 Top-1 等任务指标。容差与可接受指标损失在测试前确定。

INT8 仅在该模型、SoC 和量化工具支持时执行：划分校准集与评测集，按配套工具生成量化参数和模型，保存校准数据来源/散列；不能用评测集同时调阈值又报告精度。未支持的量化路径保留未执行，不将 `.half()` 或 `.int()` 描述为量化。

## 4. NPU-P3-03/04：采集与优化闭环

先查询已安装工具版本和 `msprof --help`；按对应文档使用应用采集入口。不要直接执行已迁移工具的过时 `msit profile` 命令。也可用所选 torch_npu 版本提供的 profiler，明确采集窗口、活动类型与导出路径。

执行顺序为：无 profiler 正式测量 → 独立短运行采 trace → 找到耗时路径 → 修改一处 → 校验输出 → 无 profiler 重测。区分 host 调度空洞、计算 kernel、H2D/D2H、格式转换、同步等待和算子编译。

将每请求分配/释放改为复用模型与 buffer；再增加两个请求槽，每个槽使用独立输入输出和完成事件，只有前一请求完成后才复写。异步结果未完成不能读取或回收内存。检查 trace 是否实际重叠，而非仅创建了多个 stream。
